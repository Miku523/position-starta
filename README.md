## 一、任务：要解决的事

广东省 2026 年集中公开招聘发了 5 张岗位表 xlsx，大兴安岭林业集团发的是 PDF 岗位表——
HR／求职者想知道「这批岗位到底卡什么」，只能一张张表翻、一个个附件下，再手工数。
我用 Lexmount 云浏览器把这些公开公告跑一遍，把**不同格式的附件归一成同一套字段**，
输出一份可核对的岗位底表，和一份能一眼看出门槛落在哪的报告。

这件事原来要人工做：19 个地址、23 个附件、9,200 行，按经验约 213 秒的机器时间要换成十几小时人工。

## 二、做法：真的跑了什么

**工具**：自建采集台（Node，无第三方依赖）+ Lexmount 云浏览器。每次采集是一个云 Session，
流程固定为 `session create → 导航 → 抽取 → 整页截图 → 下载附件 → session close`。

**三次关键实测**（失败也照实记）：

| 批次 | 地址 | 成功/失败 | 用时 | 代表 Session |
| --- | --- | --- | --- | --- |
| 首轮横向 | 13 | 11 / 2 | 164s | session_0b1a3337、session_19160ed8 |
| 招聘源探测 | 8 | 6 / 2 | 48s | session_640f113e |
| 广东岗位表重试 | 1（同一 URL 提交 5 次） | 1 / 4 | 5.4s | session_5eac7377 |
| 两源归一验证 | 2 | 2 / 0 | 12.7s | session_5eac7377、session_b881d097 |

合计 **29 次提交 / 20 成功 / 9 失败**，9 次失败里 8 次是 `navigation timeout`、1 次 `HTTP error`，
全部来自同一台服务器 `hrss.gd.gov.cn`——同一 URL 连续失败 4 次、第 5 次成功。
所以那 9,200 行不是一次跑出来的，是重试出来的。

**归一规则**（可复核，写在 `dump_canon.py` 里）：表头按「精确 → 前缀 → 包含」三轮匹配到 11 个字段
（地区／单位／岗位／岗位代码／学历／学位／专业／人数／部门／职责／等级）；
专业有多列时合并、按中文逗号切分；学历做同义归一（本科/大学本科/学士→本科）；
匹配不上的表整张跳过并记录行数，**不做猜测填充**。本次 6 张表全部命中，跳过 0 行。

## 三、结果：跑出来什么

- **9,200 个岗位**、4,519 家单位、拟聘 11,208 人，来自 2 份公告、6 张表（广东 xlsx 5 张 + 林草 PDF 1 张）。
- 学历门槛：本科 6,681（72.6%）、硕士及以上 1,343（14.6%）、大专 733（8.0%）、博士 413（4.5%）、高中 28（0.3%）。
- 专业门槛：学科教学硕士 1,414、课程与教学论 919、临床医学 808、会计学 771、计算机科学与技术 625。
  **9,200 行里「专业不限」一条都没有**——硬门槛是学历 + 专业，不是技能。
- 地区重心不在广州：湛江 1,320（14.3%）、梅州 1,059、省直 912、广州 546。
- 只招应届 1,426 个岗位（15.5%）。

方法论上还发现两件顺手的事：xlsx 的空单元格会让后面所有列左移（早已有 bug，靠 `r="B12"` 属性修好），
以及同一个 PDF 用不同 pdftotext 构建，`-layout` 的空格宽度不同，会让列边界整体走样。

## 五、复现

1. `cd source`，先把 `采集台界面.html` 复制成 `public/index.html`（`server.js` 只认这个入口），再 `node server.js` → 打开 `http://127.0.0.1:8901`
2. 引擎选「Lexmount 云浏览器」，贴公告地址，点开始采集（凭证走 `LEXMOUNT_API_KEY` / `LEXMOUNT_PROJECT_ID` / `LEXMOUNT_BASE_URL`）
3. 汇总表里点「归一为统一表」，可导出 CSV；历史记录里可勾多批次合并
4. `python dump_canon.py <batch.json> out.csv` 导底表；`python source/canon_stat.py <batch.json>` 复算统计
5. 看报告：在线访问 `/`（或 `/report/`）；本地可双击单文件 `index.html`，或 `cd report && python -m http.server 8899`

> 仓库只放源码：`source/bin/browser-cli.exe`（云浏览器 CLI）与 `source/bin/pdftotext/` 没有随包分发，复现时需自己放回这两个位置。

## 六、局限（写在前面，不藏）

- 样本只有 2 份公告，广东是省级统考、林草是央企单招，**不能代表全国招聘市场**。
- 归一规则是按这两份表写的，换省份的表格可能要调映射；跳过的表会记录，但不会补猜。
- 岗位名称 9,167 行为空——广东那份只有岗位代码与职责，没有岗位名称，这个空格不拿东西去填。
- 云浏览器对个别政务站点不稳（见台账），本次靠重试拿到结果，不是稳定可达。
- 采集台依赖本机 Node 与 `bin/browser-cli`，不是托管服务；评委复现需要自己的 API Key。
