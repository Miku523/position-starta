# 星他 STARTA · 实时数据层（可选本地服务）

站点本身是静态的（GitHub Pages），没有后端；但「实时」这件事我们没造假。分成两层：

## 第一层：页面里本来就真（静态部署也成立）

- **真时钟**：顶栏 `实时 · HH:MM:SS` 每秒走的是浏览器系统时间。
- **真倒计时**：大兴安岭公告 `2026-10-26 17:00` 截止，页面按真实时间逐秒算剩余；过期就写「已截止」。
- **真相对时间**：「数据截至 17 小时前」取自真实数据文件的写入时间（mtime），不是本次打开页面的时间。
- **真跨页签同步**：`BroadcastChannel` + `localStorage`；两个页签同时开着，一边点对标/投递，另一边立刻变色并弹「另一标签页新增对标 · 现在 N 条」。
- **数字滚动只是呈现**：`Live.num()` 用 rAF 从 0 数到真实值，目标值来自 `data/` 里的真数据；连不上服务时不会偷偷往上拨。

三种状态口径写在状态胶囊里，不混：

| 胶囊 | 含义 |
| --- | --- |
| `实时` | 连上了本地 SSE 服务，在线页签数/心跳/数据变化都由服务端推送 |
| `同步` | 没连上服务，但同浏览器多页签之间真的在同步 |
| `快照` | 单文件双击离线打开，数字来自当次数据快照，不增长 |

## 第二层：连上这个零依赖服务就更真（本地演示用）

```bash
node live/server.js --port 8790            # 默认根目录指向 ../..，即提交包/
```

- 静态服务：`/`（报告）、`/app/`（工作台）、`/app/双端/`（双端演示）、`/live/`（运营大屏）
- `GET /live/stream`：SSE 流。首包 `hello` 带全量状态（在线数、数据文件指标、进程启动时间），随后回放最近 12 条真实事件，每 4 秒一次真心跳
- `POST /live/event`：推一条真实事件（探活、采集完成、阈值告警都行），入环形缓冲并追加 `ledger.jsonl`
- `GET /live/state`：当前状态 JSON；`GET /live/health`：7 项自检（目录可读、两份 CSV 存在、能解析出行、数据新鲜度 < 7 天、SSE 在线、台账可写）
- `GET /live/`：运营大屏，数字全部现场解析 `data/岗位表_统一字段.csv` 与 `data/会话台账.csv`

细节：

- 服务直接读两份 CSV：岗位表数行数、第 3 列单位去重、第 9 列人数求和；台账数行数、第 3 列提交次数求和。
- `fs.watch` 真监听文件变化（Windows 上配 3 秒 mtime 轮询兜底），值变了才广播 `data` 事件——大屏数字跟着变，不轮询假刷新。
- 在线页签数来自真实 SSE 连接数；关掉一个页签，所有页面的胶囊数字立刻减一。
- 服务挂了，页面 2 秒内自己降级成「同步」，服务回来自动重连（退避重试 ≤30s）。
- 事件台账 `ledger.jsonl` 只追加，刷新页面后仍会回放，方便评委核对「这个数字是哪来的」。

## 文件

| 文件 | 作用 |
| --- | --- |
| `live.js` | 页面端组件（`window.Live`）：状态胶囊、数字滚动、时钟、倒计时、相对时间、跨页签、SSE 客户端；ES5、零依赖 |
| `live.css` | 状态胶囊与数字样式，继承页面 `currentColor`，不抢主题 |
| `server.js` | 零依赖 Node 服务：静态站 + SSE + 事件/状态/体检接口 + CSV 解析 + 文件监听 |
| `dashboard.html` / `dashboard.js` | 运营大屏 |
